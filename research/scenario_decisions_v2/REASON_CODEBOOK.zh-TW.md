## 分析單位與界線

每個原始有效回覆為一筆，動作與理由分開記錄。允許多標籤，不因理由像拒絕就改寫原始協助動作。這裡分析的是陳述理由，不能視為內部思考或人類動機。先導全部回覆編碼，正式研究優先同樣全量；不能只抽選漂亮例子。

| 代碼 | 納入條件 | 不足以納入的情況 |
|---|---|---|
| personal_cost | 明確考慮自己的協助成本或收益損失 | 只重述cv數字，沒有用於比較 |
| avoid_unhandled_loss | 擔心沒有人協助造成損失 | 泛稱幫忙是好事 |
| reliance_on_others | 以他人可能接手為理由 | 只有提到人數，沒有行為信念 |
| shared_benefit | 明確考慮他人或共同通行效益 | 只計算自己的報酬 |
| guaranteed_payoff | 明確偏好協助的固定報酬或最差情況保障 | 單純說cv<av但未提確定性 |
| context_use | 實際用τ、X或情境資訊連結選擇 | 原樣複述欄位 |
| unsupported_assumption | 宣稱未提供的出口、傷害、承諾或未來成功 | 明確標成可能且未當已知事實 |
| action_reason_conflict | 理由明確主張另一動作，輸出卻相反 | 猶豫或同時描述兩面利弊 |
| insufficient_reason | 空泛、無法分類或未解釋選擇 | 簡短但已有明確取捨 |

每筆另存requestID、cell、wording、rawAction、parsedAction、reasonText、labels、支持標籤的原文片段、算術問題、編碼者、codebook版本及不確定註記。推測別人會幫忙與宣稱知道別人已承諾不同，前者是信念，後者若未提供才是捏造。

## 編碼程序

先導建立規則後，正式收集前固定手冊。沒有第二位真人評分者時，明確標註單一編碼程序，不宣稱獨立人工一致性；若以LLM輔助分類，記錄其模型與提示並逐筆覆核證據片段，分類LLM不等於真值。能隱藏條件標籤時隱藏，但文字本身可能透露條件，不能宣稱完全盲化。

報告每格各標籤筆數及分母、多標籤比例不必加總100%。完整保留相反案例及所有動作理由衝突。代表例子按事前規則選取，例如固定requestID排序後每類第一筆，同時列反例；另附全量去敏感回覆與編碼。缺失與技術無效另列，不能消失於分母。修改手冊須版本化並重新編碼受影響項目。
