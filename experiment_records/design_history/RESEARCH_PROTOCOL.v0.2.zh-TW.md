# LLM agent 與賽局 agent：研究方案草案

版本：0.2，2026-11-09。此文件是待鎖定的研究設計，不是已執行的實驗或結果。不得將歷史封存資料當成新版證據。目前不啟動模擬或 API。

## 研究範圍

研究題目暫定為「基於大型語言模型與賽局理論之群眾撤離協助決策比較」。研究對象是指定模擬環境中的個人參與策略，不是真實人類行為的預測，也不是中央任務分派。

共用原模型的感知資格流程、搬運者啟動規則、Floor Field、衝突、推拉旋轉、工時與終止規則。替換的主要模組只有個人是否參與協助。歷史記憶、中央協調、語言溝通與新增危害模型不納入第一版。

LLM 與賽局取得相同資料，不代表使用相同推理：原公式只依賴其規定變數。應分開檢驗資訊增加與決策機制差異，不宣稱單一比較即可證明 LLM 推理優越。

## 可被反駁的研究問題

| 問題 | 預定檢驗 | 不足以支持的結果 |
|---|---|---|
| RQ1：LLM 是否改善群體撤離？ | 同場景、相同初始種子區塊下，比較完成率及限時撤離負擔 | 只有少數成功案例較快，卻有更多未完成 |
| RQ2：效果是否超出增加合作頻率？ | 與在獨立校準資料上匹配合作傾向的隨機策略比較，報告測試期實際合作率差距 | LLM 更常協助，卻未排除合作頻率解釋 |
| RQ3：LLM 是否值得其成本？ | 與固定簡單規則比較效率、個人負擔、API tokens 與等待時間 | 只報模擬時間，忽略運算代價 |
| RQ4：結論是否依賴額外資訊或措辭？ | 限制輸入與語義相同的中性提示敏感度檢查 | 換一個合理提示後結論反轉卻未揭露 |

不預先假定上述效果方向。若 LLM 無改善，仍分析效應大小、區間、成本與適用範圍；不能以「不顯著」等同證明兩者相同。

## 策略與資訊條件

核心策略為 OriginalGameTheory、LLM、固定規則 Heuristic，以及校準合作傾向的 RandomMatched。NoVolunteers 保留作機制負對照，不作唯一基準。

LLM 分兩個資訊條件：

- Core：只給賽局公式所需的 nearbyAgentCount、exitNonBlockage、volunteerCost、failureCost、unwillingness。
- SharedContext：現有共用觀測，增加距離、個人位置、未完成障礙與現有搬運者等欄位。

Core 用來縮小資訊差異；SharedContext 測量額外情境是否有用。兩者都不得取得未來狀態、測試結果或其他策略的答案。SharedContext 含全域統計，不能稱為嚴格局部感知。先前的 paper-agent-v1 屬於 SharedContext；目前 paper-agent-v2 已實作 Core／SharedContext 切換。

LLM 角色固定為個人：協助需付出成本，繼續撤離也是合法選項；不給「群體利益永遠優先」指令。共同說明參數意義與尺度，不能把抽象賽局成本冒稱秒數或傷亡機率。LLM 仍不等於求解原賽局均衡。模型、參數、Prompt 版本與完整文字必須在測試前固定。

Heuristic 先沿用既有規則作候選，逐一記錄常數與輸入。若調整參數，只能用開發資料；測試前凍結。不能將 heuristic 稱為 LLM 回應。

RandomMatched 先在獨立校準資料估計每個預定場景條件的 LLM 參與比例，再以凍結的機率獨立抽樣。Core 與 SharedContext 各有對應校準。不得使用最終測試答案或事後調整測試率。閉迴路軌跡改變會使實際合作率不完全一致，因此名稱表示「校準匹配」，不保證精確相等；若測試期差距大，RQ2 結論須保留。

另以共同狀態集作輔助診斷：由獨立校準場景或預先固定布局擷取合法決策狀態，所有策略回答同一批觀測。此處只分析決策傾向與敏感性，不把回答或文字解釋當作真實行為標籤，也不將孤立回答直接等同撤離效益。

## 公平性與實驗單位

正式實驗以一整次撤離執行為統計單位；單一步驟或單一行人不能視為彼此獨立的實驗樣本。

所有核心策略共用初始布局、行人位置、物理參數、決策資格與決策時機。原模型不需要決策的事件不得為 LLM 額外啟動。所有合資格者評估後才前進 CA 步驟；不以 API 預算跳過行人。耗時與實際付費須另外報告。

決策 RNG 與 Unity 物理 RNG 已分離。相同初始種子作比較區塊，不保證策略分歧後逐事件使用相同物理亂數。LLM 的遠端非確定性也須記錄，不以 temperature 較低宣稱完全可重現。

PaperRelocation 禁止 heuristic fallback。API／解析／回放失敗記為 invalid，與物理未完成分開；逐策略揭露 invalid 率及原因。預定重試規則固定，不可只為較差結果重跑。若某種策略 invalid 率高，不能僅以其有效執行子集宣稱整體較佳。

## 場景與資料切分

候選場景：出口完全阻塞、兩出口之一阻塞，以及隨機障礙房間；開放出口作機制檢查。變因優先選人群密度與搬運工時，避免一次交叉過多參數。單人極端例與 tau=1 等邊界另作規則檢查。

資料分為開發、合作率校準、最終測試三組，種子與用途不可重疊。布局家族可相同但需明確揭露；不可因此宣稱跨布局家族泛化。若研究泛化，須額外預留不同布局家族。

先完成功能與規則檢查，再另行啟動小規模先導試驗估計變異、成本與可行上限；不在本次工作執行。先導結果不能混入最終測試。正式重複次數由變異與預定效果精度決定，不以少數次執行作結論。

## 指標與統計

主要指標：共同執行上限 H 內的全員撤離比例，以及每次執行的 min(T100,H)。未完成者取 H；這是受限的完成時間負擔，不代表其真正 T100。H 在先導後、最終測試前固定，所有策略一致。上限或 H 改變必須重新標示，不混在同一主比較。

有效執行均納入完成／未完成分析。只有完成者的 T100 可以另報，但明確標成條件式次要結果。invalid 沒有可信物理終點，另外完整揭露，不填成 H 冒充物理逾時。

次要指標：實際決策合作率、每次執行的志願者總工時、每位行人的協助工時分布、停滯與搬運完成數。候選意願不等於實際搬運，兩者分開計數。API 次數、重試、tokens 與等待時間為運算成本；費用需記錄計價日期及價格來源，不能假設固定價格。

優先比較預先指定的策略差值與 95% 信賴區間，依初始種子區塊重抽樣，不能對每步紀錄直接 bootstrap。若同一種子多次遠端模型重複，作種子內巢狀資料處理。主要比較先指定為 SharedContext LLM vs GameTheory；Core、RandomMatched 與 Heuristic 用於解釋與穩健性。多場景與多比較的校正或探索性標示，須在正式測試前固定。

不以單一綜合分數掩蓋「撤離較快但個人負擔／API 成本較大」的取捨。負擔計算包含沒有協助的人，不只分析志願者。
