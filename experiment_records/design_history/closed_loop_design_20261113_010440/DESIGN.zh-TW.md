# 群體撤離正式實驗設計草案

2026-11-13，draft v0.1。這是設計整理，不是正式鎖定或執行授權；本次沒有模擬或API呼叫。第一階段response-v3固定情境研究已完成，本文件規劃第二階段的群體後果。

## 1. 問題與比較單位

主要問題：在相同初始場景、基本報酬、觸發與搬運規則下，以個人LLM取代原論文參與決策，會如何改變撤離時間、完成比例及搬運負擔？哪些預定情境的差異較大？不以LLM優於公式或更像真人為目標。

LLM只代表一名行人決定自己是否願意協助。PaperRelocation／PaperReference／PolicyWillingness共用引擎繼續處理路徑、衝突、相鄰啟動、推拉旋轉與合法放置；全域LLM指揮、人格、記憶、溝通及危險期限不納入這輪。

一個獨立比較區塊是「初始布局／行人種子」；同一run內的步數、決策或行人不能當作獨立複本。N是初始人數，X是每次當下符合條件的人數，兩者不能混用。

## 2. 比較組

| 組別 | 決策與用途 |
|---|---|
| OriginalGameTheory | 原論文調整後參與機率；主要理論參考 |
| LLM | 現有response-v3、paper-agent-v5、Core／Standard；主要研究對象 |
| NoVolunteers | 不產生協助意願；檢查無搬運時場景是否仍可逃生，不保證一定失敗 |
| RandomMatched（可選補充） | 每次用獨立隨機數與固定校準p決定意願；須先獨立校準，不能使用舊3,000筆、目前先導或FinalTest結果設定p |

核心三組足以描述政策差異，但不足以把差異歸因於「平均參與率以外的選擇方式」。若要研究後者，需在正式鎖定前決定納入RandomMatched，不能看到正式結果才挑選比較組。MockHeuristic不能冒充LLM或無志工。

## 3. 精簡場景矩陣（候選，待幾何驗證）

固定21×21格、單一寬3出口、總計5個可搬障礙。改變出口前相關障礙B，其餘放在不鄰接出口的背景位置。這比舊先導0／2／5「總量與阻塞同時增加」更容易解讀。

| 因素 | 候選層級 | 解讀 |
|---|---|---|
| 出口相關障礙B | 0、2、5 | Paper Moore出口前集合有5格，初始tau預期1、.6、0；以實際幾何計算確認 |
| 初始人數N | 10、30 | 同8×8生成區；同時改變人數、密度與競爭，不能稱為純X效應 |
| 協助成本cv | .05、.2 | 沿用已研究的中心／較高成本；av=.5、omega5固定；不是搬運秒數 |

主比較：B∈{2,5}×N∈{10,30}×cv∈{.05,.2}，共8格。
無阻塞程序控制：B=0×N∈{10,30}，cv=.05，共2格；沒有賽局時不必重複成本層級。
**合計10個場景設定，核心三組每個種子30輪。** NoVolunteers在不同cv下可能物理相同，這些重複只作不變性／配對檢查，不能增加獨立樣本數。

候選座標（尚未實際生成）：出口(9,0)到(11,0)，出口前集合(8..12,1)。B2用(9,1)、(10,1)，另設水平鏡像；B5佔滿5格。背景候選[(2,5),(18,5),(2,10),(18,10),(10,17)]，B0用5格、B2用前3格、B5不用。每格必須通過邊界、重疊、spawn、出口關聯與搬運目的地可行性檢查；不是把這組座標直接當成已驗證地圖。

鏡像是預定的布局干擾因素，成對政策用同一方向；30個FinalTest種子候選平均分15左／15右。所有成本及政策共用同一布局／初始行人清單，同一種子N10取N30清單前10人；需要新場景manifest支援。

**仍存在的混雜：** 固定總量不等於純tau實驗。B變化同時改變出口附近幾何與需要處理的障礙工作量；本輪稱「布局情境比較」，不宣稱單獨識別tau因果效果。背景位置也須完整保存。出口寬度、出口數與障礙總量暫不再加因子，避免矩陣失控；其他建築布局另作後續穩健性研究。

## 4. 共用設定與時間界線

沿用先導已用的物理設定：kS=3、kD=1、kA=5、移動temperature=1、Combined、PaperYielder、diffusion=.3、decay=.1、anticipationRadius6、manipulationSteps1、abandonDensity=.01、densityWindow10、replanAfter10、NextToWallsOrObstacles、destinationExitDistance2、yielderDefectionCost1／friction0、visibility20、cellSize1、stepInterval.3。八鄰域與斜向成本不改；模型操作化限制沿用原模型對照表。

LLM沿用gpt-6-luna／response-v3／v5 Core Standard，none、temperature.15、max_completion_tokens220，每次新請求、無歷史、禁用mock fallback。若模型不可用或版本更換，須另登記／鎖定，不臨時代換。

候選共同H=300模擬步，僅是觀測／截尾界線，不是已驗證的火災期限，也不提供給LLM當壓力。H尚未鎖定；N30的開發先導須確認量測與可用性，再於看FinalTest前固定。物理步數與API牆鐘耗時分開報告，不能把API延遲當成模擬中的撤離延遲。

不能沿用舊每輪100次請求上限：N30、B5的第一輪判斷就可能150次。正式額度尚未指定；保守邏輯上界H×N×總障礙=45,000／最高負載run（實際通常少得多，並非預定呼叫數）。須先由開發先導估計實際工作量，再明列每輪／整批保留額度與停止規則。若上限小於邏輯上界，必須承認可能發生技術中止；不能把低參與、重複判斷而撞上限的run排除後只分析其餘成功者。

## 5. 種子、樣本數與資料分離

候選Development：41001–41006（6個）；Calibration：42001–42010（10個，可選組才需收集）；FinalTest：51001–51030（30個）。目前目錄／保存config的歷史重疊檢查另存；正式鎖定前仍需再次全量確認。這些只是草案保留，不代表已跑或已凍結。

核心方案正式數量：10設定×3政策×30種子=900輪，其中300輪標LLM，240輪屬阻塞情境、可能呼叫API。開發若完整覆蓋6種子則180輪，另登記額度後才可執行；種子不能因結果不好替換。30個種子是候選可行性／精度設計，不是已完成power分析或效果保證，需用開發資料的配對變異與運算成本在FinalTest前確認。

若納入RandomMatched：8個阻塞設定×10獨立Calibration種子=80輪LLM校準；每設定以校準期所有有效決策的C比例估計固定p（決策加權，非逐run等權），另報各run與種子的變異。正式增加8×30=240輪，共1,140輪。B0沒有決策，不能虛構校準p，無需再加入此組。

校準p即使為1也照實保留，不因不夠有趣重抽。它只匹配校準期設定層級的整體意願，FinalTest受回饋影響，實際參與率不保證相同；差異不能直接稱為智能或更會選人。校準檔需綁定responseProtocol、prompt、模型、Core、場景template hash、物理設定、H、來源鎖定與不重疊種子。

舊12輪動態先導、固定情境正式資料、合成與回放均不得作本輪FinalTest或RandomMatched校準。相同種子只保證核對相同初始條件，政策分歧後亂數取用次數也會分歧，不宣稱各步遭遇完全相同隨機事件。

## 6. 指標與預定比較

主指標：全體行人的受限平均撤離步數 A_H = (1/N)Σ_i min(T_i,H)，未撤離者記H。等價為 t=0..H−1 時每步未撤離人數之和除N；提早全員撤離後的未撤離數延伸為0。越小代表這個共同H內的撤離負擔越少。

預定主要對比：對每個FinalTest種子，先對8個阻塞設定等權平均(LLM A_H − Original A_H)，再跨種子平均。保留方向：負值表示本設定分布下LLM較快，正值表示較慢，不預設方向。B0控制不併入此主要平均；NoVolunteers與場景交互差異為次要／探索性。若採區間，整個base seed區塊一起重抽，保留同種子跨設定／政策相依；不把900輪或每次決策都當獨立n。方法與次數仍須在正式分析gate凍結，不事後挑顯著對比。

| 次要指標 | 規則 |
|---|---|
| E_H/N、全員撤離比例 | 依共同H計算；合法timeout保留 |
| T100 | 只在全員完成時有精確值；不能只平均完成者來替代主指標 |
| 志工形成 | 願意次數／當下機會、啟動與完成搬運、首個啟動步數；區分未觸發、拒絕與錯誤 |
| 搬運負擔 | 全體初始行人含0：active-handler總步數、人均／最大負擔、零貢獻比例；可加Gini，總工作0時另標no-work，不當作公平證據 |
| 成本與品質 | 邏輯API／HTTP、token、耗時、invalid／timeout／技術上限事件分列 |

現有effort只涵蓋啟動後的active-handler步數，不含接近障礙前的走路；不能寫成完整協助成本。願意幫忙與本人晚撤離之關聯不直接作因果解釋。

## 7. 正式執行前要補的東西

1. 固定布局／行人manifest及產生器：區分total obstacles與initial blocked tasks，保存template hash、實際幾何hash、鏡像與N10/N30對應。
2. 新的strict runner／零API幾何gate；舊BoundedGamePilot只接受12個工作、且把總障礙等同阻塞工作，不能直接拿來跑本矩陣。
3. 群體分析補A_H、截尾、零負擔、seed區塊配對與技術失敗處理；核對新布局可搬、NoVolunteers功能及真實回覆串接。
4. 群體正式鎖定gate改為目前Core／三主組及可選RandomMatched。舊tools/research_plan.py仍要求SharedContext、Mock與校準全覆蓋，是舊方向，不能沿用當本方案已ready。
5. 如納入RandomMatched，擴充tools/agent_research.py與CooperationCalibration.Load的版本／template／source綁定；現有promptVersion與conditionKey不足以區分同v5下v1/v3輸出與新布局。
6. 先登記開發先導與額度→檢查幾何／串接／H／成本→決定是否納入RandomMatched並獨立校準→凍結FinalTest種子、H、樣本、比較、額度及失敗規則→才跑正式研究。

場景保留標準依幾何合法與機制可量測，不依哪個政策勝出、差異是否顯著或是否全員撤離來挑選；合法的停滯／全未撤離也是結果。

正式期若invalid、來源漂移、API失敗或資源上限觸發，停止整批並保留所有已跑／未跑紀錄；不以拒絕補值、mock替代、刪掉壞結果或加抽救結果。timeout是共同H下合法未完成，與技術invalid不同。是否／如何分析技術中止的批次須在gate固定，不可事後只分析成功案例。
